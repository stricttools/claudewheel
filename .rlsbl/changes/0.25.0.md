## 0.25.0

Profile ownership overhaul: per-profile token stores with declared plan tiers, session-aware delete/rename guards, an interactive deletion checklist, a sessions overview screen, and marketplace/plugin suppression.

<details>
<summary>Context</summary>

This is the first release cut from the profile-ownership program: a run of
work that moved every piece of a profile's identity into the profile
directory itself, and taught claudewheel to see the Claude Code sessions
holding a profile before it deletes or renames one.

Migrating the CLI's machine-readable output to the framework's newer shape is
deliberately left out. It depends on behaviour that only exists in the
framework's next release, so it waits for that release rather than being
developed against an unpublished dependency.

</details>

### Breaking

- **The orphan-token surfaces are gone.** A token entry with no profile directory behind it cannot exist once the token lives inside the profile, so the `orphan-tokens` health check, the `profile fix-auth` branch that removed a stale entry, and the TUI's `T` review hotkey with its startup notice are all removed. `profile fix-auth` now refuses a name with no profile directory instead.

### Features

- **`claudewheel profile` subcommands now explain themselves in `--help`.** Every command in the group -- create, delete, show, rename, fix-auth and check-tokens -- carries a full description of what it does and what it refuses, instead of a one-line label.
- **Each profile now stores its own OAuth token.** The token, its dates and its plan-tier fields move out of the central `~/.claudewheel/tokens.json` and into `profiles/<name>/.claudewheel/token.json`, written 0600 inside a 0700 directory. A rename carries the token with the profile directory and a delete removes it, so there is no second place to fall out of step, and an unreadable entry now fails the token health checks naming that one profile instead of degrading the whole run. Move an existing `tokens.json` entry by hand: write its object into that path for each profile, then delete the central file.
- **Every profile now states which plan its account is on.** Claude Code resolves its subscription tier from the launch environment and only from there when auth is a stored setup token, so an undeclared profile launched with the tier null and tier-dependent features failing closed. A single composite picker now declares both fields as one pair, from three surfaces that store identical output: the create flow asks before capturing a token, a pre-launch prompt asks when an existing profile has none, and `claudewheel profile set-plan <name> <plan>` declares one for scripted use. Values are validated against the sets Claude Code recognizes -- an unrecognized one is a hard error naming the valid plans -- and replacing a profile's token clears the declaration so it is asked again.
- **Deleting a profile now offers to stop what is holding it.**  A deleted profile used to reappear as an empty husk: every surviving Claude Code process still carries `CLAUDE_CONFIG_DIR` pointing at the directory, and any invocation of the client recreates its config directory before doing anything else. The TUI now lists every live process registered under the profile -- name, uptime and resident memory, the daemon and its workers pre-ticked and nothing else -- stops exactly what you tick without leaving the screen, and only then removes the directory. Anything left running is named in the result instead of the deletion claiming the directory is gone; `claudewheel profile delete` names the same survivors on the scripted path.
- **Launched profiles no longer collect the plugin marketplace.** Claude Code used to clone the official plugin marketplace into a profile on first launch and install three language-server plugins from it -- six to ten megabytes per profile, for something no profile asked for. Every named profile now launches with `CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL=1`; the vanilla `~/.claude` path strips it like every other profile-owned variable. The suppression is one-way per profile: once Claude Code records the install as blocked, removing the variable does not make it retry.
- **New `claudewheel purge-plugins` removes plugin trees profiles already collected.** One profile (`--profile`) or all of them (`--all-profiles`): it names each profile's marketplace clone and installed plugins, removes the tree and reports the bytes freed. `--dry-run` reports the inventory without removing anything. It is deliberately separate from the canonical reconciliation, which is exact and would otherwise delete plugin state on every run; the `default` profile is never touched, and a symlinked `plugins` entry is left alone.
- **The sessions overview.** Uppercase `S` in the launcher opens a scrolling list of every Claude Code session registered under the selected profile -- name, directory, uptime, resident memory, and the session you are sitting in marked -- with the focused row expanded to its pid, session id and version. It is a snapshot: `r` re-reads the registry, nothing refreshes under the cursor, and `p` deletes the registry files of sessions whose processes are provably gone.
- **`claude-sonnet-5` is selectable.** The model segment offers it, and an options.json carrying it is recognised as holding a shipped default rather than a hand-added value.
- **The docs cover the sessions overview.** The README key list and the getting-started guide now name the uppercase `S` key, note that it no longer starts a fuzzy search, and describe the overview screen's refresh and prune keys.

### Fixes

- **Delete and rename now really see live sessions.** The running check scanned for a `sessions/*.pid` filename Claude Code does not write, so it always reported zero: a profile with a live Claude Code session could be deleted or renamed without warning. It now reads the real `sessions/<pid>.json` registry, drops stale files and recycled PIDs by matching the process start time, and refuses only for a live interactive session -- background jobs and daemons no longer block.
- **Launching a profile no longer writes into its `.credentials.json`.** claudewheel used to copy the declared plan-tier fields into Claude Code's credential file at launch; that stub made the `auth-shadow` health check warn on every launched profile, made `profile show` report credentials that do not exist, and was rewritten on the next launch after `profile fix-auth` stripped it. The tier reaches Claude Code through the launch environment instead, `fix-auth` no longer copies tier fields back out of the credential block, and a credential file left holding nothing is removed rather than kept as an empty object.
- **A launch with no terminal no longer believes it is interactive.** Whether a launch may prompt is now derived from having a controlling terminal rather than from print mode being off, so a flag-driven headless launch reaches the non-interactive branch of every pre-launch step instead of trying to open a terminal that does not exist. A headless launch of a profile with no declared plan fails naming `claudewheel profile set-plan`.
- **The vanilla `default` profile no longer reaches a data-destruction dialogue.** Deleting it from the TUI used to show the page about destroying real data and advertise a `profile delete --force-delete-data` the store would then refuse. Both the TUI and the CLI now answer the reserved name first, with a message that names no command, because none could succeed: `~/.claude` is Claude Code's own directory.
- **A live session's registry file survives a prune.** Pruning the sessions overview no longer risks deleting the registry file of a session that started while the screen was open: a file is removed only when it still holds the very record the snapshot read, so a pid the kernel recycled to a new Claude Code session keeps its file -- and the profile delete and rename guards keep seeing it.
- **A blank `procStart` no longer makes a running session look dead.** A registry record whose kernel start-time field is empty is read as carrying no token rather than a mismatching one, so the session stays visible to the sessions overview, the prune key leaves its file alone, and profile delete and rename still refuse while it is running.
