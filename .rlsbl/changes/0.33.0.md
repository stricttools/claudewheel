## 0.33.0

A guardrail rule that refuses a shell sleep in every managed profile.

<details>
<summary>Context</summary>

An agent that runs `sleep` to wait for something is spending a turn on
nothing: the harness reports background work when it finishes, and the
state being waited on can simply be read. The new hard-deny rule refuses
`sleep` wherever it begins a shell command and answers with that steering,
while a word that merely contains "sleep" -- `nosleep`, `./sleepwalker`,
`echo sleep`, `grep sleep file` -- still runs.

</details>

### Features

- **Every managed profile now refuses a shell `sleep`.** The guardrail hook denies `sleep` wherever it begins a shell command -- at the start, after a separator, or opening a subshell -- and tells the agent to read the state it is waiting on instead of padding the turn; a word that merely contains "sleep" still runs.

### Fixes

- **The package metadata names the repository where it actually lives.** The repository moved to the stricttools organisation, so the npm page's repository and issue links pointed at the old owner, and a publish whose build attestation named the new one was rejected.
